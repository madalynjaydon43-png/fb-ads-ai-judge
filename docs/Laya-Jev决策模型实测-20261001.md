## 三、我实测了什么

装进独立虚拟环境（`python -m venv` 新建，Laya 0.3.22 + torch 2.14.1 CPU 版），
把 100 条广告压成 448~533 字符的结构化文本（**样本量字段直接用你新加的 `sample`**），
问同一个问题："这条广告现在该怎么处置？"（4 选 1：暂停 / 减预算 / 观察 / 加预算）。

### 实验 1：中文提问（我第一版，**这个不公平，我自己纠正**）

| 指标 | 结果 |
|---|---|
| 严格准确率 | **16.0%**（随机猜是 25%） |
| 选项顺序翻转率 | **98/100 = 98%** |
| 倒序那一轮 | 100 条**全判同一个动作** |
| 置信度 | 0.253~0.280（4 选 1 的均匀分布就是 0.25）→ 完全没在区分 |

问题在于：我给**英文 checkpoint** 喂了中文问题。重跑。

### 实验 2：全英文提问（公平版）

| 指标 | 结果 |
|---|---|
| 严格准确率 | **37.0%** |
| 业务口径准确率 | **37.0%** |
| 动作分布 | "保持或加预算" 73 条 + "暂停" 27 条 —— **只有两个标签** |
| 置信度 | 0.279~0.455，中位 0.330 |

**关键**：37.0% ≈ 38.0%（什么都不做、只喊一个动作的严格基线）。
也就是说它**没有在做区分**，只是换了个标签一直喊。

### 实验 3：4 个选项顺序全轮转（位置偏置的真实伤害）

| 轮次 | 选项顺序（首项） | 严格准确率 | 动作分布 |
|---|---|---:|---|
| 0 | pause 打头 | 37.0% | 加预算 75 / 暂停 25 |
| 1 | decrease 打头 | **10.0%** | **暂停 100** |
| 2 | observe 打头 | 37.0% | 加预算 87 |
| 3 | increase 打头 | 39.0% | 加预算 76 |

**同一份数据，只把选项顺序转一圈，准确率从 10% 飘到 39%——极差 29 个百分点。**
任意两轮之间的平均翻转率 **52.7%**。
（对照：AnyJev 论文报原始 logit 翻转率 23%，L0 修完降到 7.3%。）

### 实验 4：把 4 轮概率平均掉（AnyJev L0 的核心动作，我自己实现）

| | 严格准确率 |
|---|---:|
| 轮转平均后 | **37.0%** |
| 单跑正向那一轮 | 37.0% |

**一点没涨。** 只改了 18% 的答案。动作分布仍是"加预算 61 / 暂停 39"——**还是不看数据**。

## 四、三条硬结论

### 1. 「位置偏置」是真的，而且比你想的严重

Laya 零样本下，**决定它答案的主要是"选项排在第几个"，不是"这条广告什么样"**。
这解释了你自己遇到的那个 8% 横跳——LLM 一次性批量输出时会互相影响口径，
而这类决策模型是**每个位置都有系统性偏好**。

### 2. 轮转平均（L0）只能修"摆动"，不能补"判断力"

这是本轮最有价值的一条。AnyJev 的 L0 让翻转率从 23% 降到 7.3% **且零标注**——
但注意它论文里的场景：那个模型**本来就会做那道题**（准确率 0.747）。
对**本来就不会做**的模型（Laya 零样本 = 随机水平），L0 平均下来的还是噪声，
于是准确率纹丝不动。

**这和我在你 LLM 上做的"多数派投票"实验结论完全一致**：
投票能把横跳的痕迹抹平，不会让它变准。

### 3. 官方自己承认：天花板是 73.5%

Laya 和 AnyJev 两个 README 里出现了**同一个数字**，引用的是同一个基准
（LocalLLaMA/typed-decisions，2000 decisions）：

> **teacher self-agreement ceiling = 0.735**
> 「标准答案是某个模型三次采样的平均值；该模型自己再采一次，只有 **73.5%** 的概率和它一致。」

翻译：**当"正确答案"是某个 LLM 的意见时，那个 LLM 自己都只有 73.5% 和自己一致。**
超过 73.5% 的部分没有东西可学——那里是噪声。

**这是对我上一轮结论的独立第三方确认**：你的 68.9%（业务口径）已经贴着这条天花板了。
不是你的模型差，是这道题的可达上限就在这儿。

## 五、真正对你有用的三件事（跟换不换模型无关）

1. **校准置信度 + 弃权**（这是这类项目唯一成熟的工业件）
   - Laya：`min_confidence=0.85` → 低于阈值的答案标 `low_confidence`，转人工
   - AnyJev：在 ≤5% 错误率下可自动化的比例，从 7.7% → **52.0%**
   - 这正是我们说的"当筛选器、不当判决"的工程形态。**但现在 Laya 的置信度是均匀的（0.33），
     用不了** —— 它得先在你的数据上微调过，概率才有意义。

2. **微调底座（这是它真正的价值）**
   - Laya：Kaggle 免费 2×T4，约 30k 问题跑 4 epochs ≈ **4~5 小时**，
     官方实测准确率从 0.362（零样本）跳到 **0.766**
   - AnyJev L2：每题 **100~300 条标注**，闭式解，秒级完成，**成本比一次普通前向还低（0.68×）**
   - ⚠️ **但标注不能用你那张`场景答案表`** —— 它是由隐藏列决定的，标进去等于学噪声。
     要用**真实后续结果**当标签。

3. **零标注的位置偏置修正**（可以马上用，配合任何模型）
   - 把同一批数据换个选项顺序再问一遍，概率对齐后平均。
   - 代价：K 个选项要跑 K 次；AnyJev 有个 rotation budget 能压到约 7/18 次。

## 六、你这台机器的资源约束（决定怎么落地）

| 项 | 实测 |

| 内存 | 本机常年吃紧（加载模型时约需 1.7GB），跑之前先关浏览器 |

→ **适合每天批量跑一次（100 条 ≈ 2.5 分钟），不适合你原来"每 3 分钟一轮"的调度节奏。**

## 七、下一步（按优先级）

1. **先改标签来源**：把"LLM 觉得该给什么动作"换成"**这条广告后 3 天的真实结果**"。
   标签客观化了，73.5% 那堵墙才会倒。这一步不做，换什么模型/算法都是原地打转。
2. **然后**才谈上模型：拿 100~300 条真标签，AnyJev L2（或 Laya 微调）挂上去，
   用校准置信度做"够自信→自动执行 / 不够→转人工"。
3. **花钱的动作（加/减预算）始终留人工终审** —— 实测这两个恰好是所有模型最弱的两档。

**口径说明**
- **严格口径** = 真值说「保持或加预算」时，必须给 `increase_budget` 才算对

- **兜底** = 批次调用失败后程序自动补的 `observe`，不算模型判断

## 三、读数

1. **四个能跑完的模型，严格口径 45%~49%、业务口径 59%~68%** —— 差异在噪声范围内，没有一个显著更好。
2. **没有一个打赢「什么都不做」**（业务口径 72%）。这不是模型差，是这张答案表的「正确动作」由一个模型看不见的隐藏列决定（详见此前审计）。**换模型解决不了这个问题。**
3. **速度差 4 倍以上**：STDS 38 秒 / dsv4.1-flash 71 秒 / dsv4-pro 154 秒 / hy3 157 秒；hy4-preview 与 kimi-k3 **10 分钟都跑不完 100 条**。按你 3 分钟一轮的调度节奏，后两个直接不可用。
4. **性格差异倒是看得见**：
   - STDS 最保守 —— 该减预算的 18 条**一条都没减**（0/18）
   - deepseek-v4.1-flash 最敢减 —— 6/18，但误杀也涨到 4
   - hy3 居中（3/18）
   想让它「敢减预算」，v4.1-flash 是唯一有明显变化的，代价是误杀变多。
5. **理由质量**：deepseek-v4.1-flash 的 reason 写得最具体（会自己报「7天出7单、近三天 ROAS 1.55、加购 47 只成 7 单」），hy3 次之。

## 四、怎么接（改三行即可）

编辑 `ai_config.json`：

```json
{
  "base_url": "http://127.0.0.1:7865/v1",
  "api_key": "<本机管理端生成的 key>",
  "model": "hy3",
  ...
}
```

- 想**完全免费** → `"model": "hy3"`（实测 cost_per_1k=0，代价是慢 4 倍）
- 想**保持最快** → 不动，继续用 `STDS`
- 想**让它敢减预算** → `"model": "deepseek-v4.1-flash"`（该减召回 0/18 → 6/18）

> ⚠️ 改完必须**重启工具窗口**才生效 —— Python 只在进程启动那一刻读配置。

## 五、同时改掉的一件事：样本量不再让模型数

Prompt 里原本要求模型「自报样本量」，结果它**数错**（把「7 天出 6 单」写成「6 天有单共 6 单」，9 轮反复这么写）。

现在改成**由代码算好再喂给它**：每条广告新增 `sample` 字段 —— 窗口天数 / 出单天数 / 总单数 / 花了钱但零单的天数 / **最近三天**单数与 ROAS / 最长连续烧钱零单天数 / 首次出单日期，并要求 reason 用统一句式「X天里出Y单（出单天数Z）」引用，**明令禁止自己数**。

已验证：700 行 × 2 项断言 = **200 项全过**，数字与逐日明细逐条一致。那条短袖 T 恤现在是「**7天里出6单（出单天数5），近三天3单 ROAS 4.12，最长连续烧钱零单 2 天**」。

## 六、还没解决的（说实话）

把预算开关交给这套 AI，目前仍然不成立 —— 它的弱点不在模型，在这三处：

1. **答案表没有标准答案**（隐藏列决定正确动作）
2. **判分口径会反转结论**（严格口径它赢不作为 11 个点，业务口径输 5 个点）
3. **加预算 / 减预算恰好是它最差的两档**（40.8% / 7.1%）

能用的姿势：**当筛选器，不当判决者** —— 该暂停的它能认出六成、几乎不冤枉人；把 100 条收缩到十几条要你亲自看的，附上理由。

# 怎么测这份数据（给「拿别的 agent 跑我的代码」这件事）

> 生成 2026-10-02。目录：`fb_ad_analysis/测试数据-5天/`

---

## 一、这份数据是什么

一共造了 **10 天**，但**只给你前 5 天**：

| 文件 | 是什么 | 给谁看 |
|---|---|---|
| **`模拟数据_前5天.csv`** | 8 条广告 × 5 天 = 40 行 × 28 列，**这就是要判的那份** | ✅ 交给要测的 agent |
| `真值_后5天.csv` | 同样 8 条广告的后 5 天，**这是后来真的发生的事** | ❌ 判卷前别给 |
| `答案表_别提前看.csv` | 每条的最优动作 + 可接受动作 + **全部现算的数字** | ❌ 判卷前别给 |
| `设计说明.md` | 每条广告埋了什么坑、为什么这么造 | ❌ 判卷前别给 |
| `_自审报告.txt` | 生成时的自审结果（漏斗单调 / 派生列对得上 / 比率在合理带） | 想核对就看 |

> ⚠️ **后三个带 ❌ 的文件不在 GitHub 仓库里**（仓库只收了数据 + 本说明）——
> 仓库是公开的，被测的 agent 能直接读到答案就没意义了。
> 判卷依据只保存在你本地这个目录里。

**为什么只给 5 天**：判分的依据不是「我写的标准答案」，而是**后 5 天真的发生了什么**。
这才是投手真正的处境 —— 4 月 1 日你只能看前 5 天，4 月 6 日才知道当初该关还是该留。

## 二、这份数据是怎么设计的（重要，决定它有没有测试价值）

**它不是「用某个隐藏函数算出的答案」。** 之前那份 v3 模拟数据就是这么做的 ——
「正确动作」由一个叫「潜在质量档」的隐藏列 100% 决定，而那一列不在可见数据里。
结果是任何模型都只能到 52~58%，**测的是链路通不通，不是判断力**。

这份反过来：先按**投放情境**构造数据（该关的、该加的、样本不够的、优化目标不同的、
落地页坏的、素材坏的、已暂停的、学习期），答案由**情境**决定；
而情境留下的痕迹必须在可见列里**能被推理出来**。所以判对了 = 真的判断力。

漏斗也是**链式比率推出来的**（点击 → 加购 → 结账 → 支付 → 购买），
不是手写的 —— 所以不会出现「6 次点击出 2 单」这种一眼假的穿帮。
所有派生列（频次 / CPC / CPM / 独立点击单价 / 购物转化价值）都现算，自审会对账。

## 三、怎么跑（三步）

### 1. 先自检列齐不齐

```bash
cd fb-ads-ai-judge
python learn_cycle.py check --csv "..\fb_ad_analysis\测试数据-5天\模拟数据_前5天.csv"
```

期望输出：`必须的指标列：认出 14 / 14` + `结论：列齐全，可以直接喂。`

### 2. 交给 agent 判

仓库：<https://github.com/madalynjaydon43-png/fb-ads-ai-judge>（public，`main` 分支）

把 `模拟数据_前5天.csv` 和**下面这段要求**一起给它：

> 这是 8 条 Facebook 广告的 5 天逐日数据（CSV，广告级粒度，28 列）。
> 请对**每一条**给出：动作（increase_budget / decrease_budget / pause / observe）+
> 理由（必须引用具体数字：花费、点击、单数、频次、漏斗各环的通过率）。
> 输出 JSON 数组，**一条都不能少**。
> 提示：文件里有几列是「决定别的数字怎么读」的口径列（投放状态、归因窗口、成效指标、
> 竞争排名），请先读它们再下结论。

### 3. 判卷

打开 `答案表_别提前看.csv`，逐条对：

- **最优动作** 命中 → 这一条满分
- 落在 **也可接受** 范围里 → 部分分（该列写了每个变体的得失）
- 命中 **加分项**（如 A5 指出病根在落地页、A6 指出病根在素材）→ 额外加分

再对一遍 `真值_后5天.csv`：如果 agent 给的动作和后 5 天的真实走向**方向相反**，
那就是**真误判**（不是表述问题）。

## 四、判卷时重点看这 5 条（这 5 条是这份数据的真正考点）

| 广告 | 埋的坑 | 判错的后果 |
|---|---|---|
| **A2** | 5 天 0 单，但点击量极低 | 按「零单就关」= **误杀一个正在起量的广告** |
| **A3** | 0 单，但点击量够、顶格、频次冲到 5+ | 该关没关 = **再白花一笔** |
| **A4** | 优化目标是**加购**（不是购买） | 按「购买少」关 = **打错靶子** |
| **A6** | 3 秒播放很高，但**平均只看了 2.1 秒** | 给 decrease_budget = **用药不对症**（病根在素材不在出价） |
| **A7** | 窗口末尾两天**真实零花费 + status=PAUSED** | 说「建议关停」= **把暂停当成跑坏** |

另外 A1 是唯一该 `increase_budget` 的；A5 的坑是**重复点击率 45%**（病根在落地页）；
A8 是**学习期**（头两天样本根本不够）。

## 六、这份数据顺手抓出来的一个真 bug（已修）

生成完第一次用真代码跑，发现 **A7 的 `status` 被读成 `ACTIVE`** ——
它前 3 天 ACTIVE、后 2 天 PAUSED，而加载器取的是**第一个**非空状态。

后果不轻：prompt 明写「status 非 ACTIVE 不得给 increase_budget」，
一条**已经被暂停**的广告被报成在投，等于把最该拦住的那条规则绕了过去，
还顺手给一条停投的广告建议加预算。

**已修**：状态改成取窗口里**最后一天**的值（投放状态是时点事实，最新值才有意义），
并补了 2 个回归测试。测试 69 → **71/71**，静态三查 0 问题。
